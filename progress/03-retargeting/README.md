# 阶段 03：映射、双层校准、稳定驱动与配置

日期：2026-09-29。实现范围对应项目计划 V1-07、08、09、10、11 的核心逻辑；界面、摄像头与模型适配由应用集成阶段验证。

## 本阶段实现

- 使用 MediaPipe 具名输入通道匹配模型实际表情，支持 VRM0/VRM1 语义别名、一个输入多个目标、多个输入加权合成。缺少绑定的表情不作为可驱动目标。整体微笑、双眼合并等近似方案必须确认后才生效。
- 每个目标只经过一次合成；删除映射时清除上一帧残留值；手动试动覆盖当前输出，不污染真实追踪状态。
- 个人校准与模型参数分开。中性脸、闭眼、张嘴、微笑和可选抬眉步骤只接受有效、唯一时间戳的人脸样本，检查样本数与动作幅度，支持失败重试。保存中性姿态、各通道基线、幅度和采样质量。
- 角色参数包含通道增益、死区、上下限、响应曲线、头部三轴限幅及强度；自然/增强风格只调整现有输出。
- 依据时间间隔进行自适应平滑，快速眨眼/张嘴使用较快响应。拒绝过期、倒序和明显未来帧；结果停滞同样触发丢失。短暂保持后回正，恢复时渐变；镜像显示不参与数据语义。
- IndexedDB 分别存储模型哈希配置、个人校准与界面设置；单独重置个人校准、清除全部配置。JSON 导入/导出验证版本、哈希、通道、目标、重复规则、非法字段、非有限数值及上下限，并对有限越界参数做安全钳制。

## 代码入口

- `src/core/retargeting/index.ts`：`createDefaultProfile`、`suggestMappings`、`INPUT_CHANNELS`、`CalibrationCollector`、`Retargeter`。
- `src/core/profiles/index.ts`：`ProfileRepository`、`parseBundle`、`serializeBundle` 与各类型校验函数。
- 时间戳约定：实时帧的 `timestamp` 与 `Retargeter.update` 的 `nowMs` 必须使用同一单调毫秒时钟；回放层需要转换到这一时钟。
- 个人校准质量字段表示有效采样量和动作区分度的工程指标，不表示追踪器置信度。

## 自动验证

运行命令：`node node_modules/vitest/vitest.mjs run tests/unit/retargeting.test.ts tests/unit/profiles.test.ts`。

共 17 项单元测试：10 项映射/校准/平滑测试，7 项配置/IndexedDB 测试。覆盖版本别名、空绑定、近似确认、多对多合成、删除残留、手动覆盖、双层参数、头部限幅、帧时序、遮挡回正与恢复、静态抖动与短眨眼、校准重试、JSON 防错、哈希隔离及删除后的重新打开。

抖动测试使用固定合成参数片段，验证输出 RMS 相对无平滑输入至少降低 30%；这只是算法回归门槛，不能代表真实摄像头或所有模型达到该指标。

## 仍需人工验收

- 真实摄像头下的左右方向、姿态基线、眼镜/光照边界及表情自然程度。
- 三名测试者各 20 次动作、60 秒中性脸误触发、真实延迟与 30 分钟资源稳定性。
- VRM0/VRM1 实际素材的二值表情、眨眼/口型/视线覆盖冲突，由模型适配器和人工视觉检查共同验收。
- 浏览器禁用存储、配额不足及跨标签页占用等实际异常。

本阶段没有记录或保存摄像头图像，没有引入模型生成、云服务或收费 API。

## 2026-09-30 集成补充

- 配置写入采用串行队列和操作版本号。清除操作等待已经开始的写入完成后再删除，跳过过期排队任务；晚到的 JSON 文件读取、旧保存回调和启动恢复结果不会覆盖清除后的状态。清除和导入同时重建校准采集会话，避免旧采集器回写。
- 个人校准界面等待 IndexedDB 写入完成后才显示成功；保存失败会保留错误提示。采集中断、重置和重新采集均有明确状态，保存期间不启动下一轮采样。
- 界面设置修改阻止旧的异步恢复覆盖当前选择；修改模型参数会停止旧参数回放，接入新的驱动配置。
- 参数录制保留采集时刻相对时间并深复制帧，最长 30 秒、最多 1000 帧；以固定 60 Hz 虚拟时钟重新驱动，包含丢失、保持、回正和恢复。导入拒绝未知字段、未知通道、非法姿态/系数、倒序或重复时间戳、超量数据。

新增 `tests/unit/configuration.test.ts`（3 项）和 `tests/unit/recording.test.ts`（4 项）。配置测试用真实 IndexedDB API 的内存实现人为延迟一次跨存储保存，再执行清除并重新打开数据库，验证旧校准不复活；回放测试验证相同输入逐帧产生相同输出。编译和单元测试结果记录于最终交付阶段。
