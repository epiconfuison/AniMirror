# AR-Capture V1 最终测试操作指南

编写日期：2026-10-01。对象：在 Windows 电脑上手动测试 AniMirror 的使用者。

**当前核心功能已实现，剩下的是最终验收，以及验收发现问题后的修复。** 自动化已验证工程链路；本指南用于补齐真实摄像头、动漫模型、三名测试者和持续运行证据。所有测试通过后，才可以把第一版标记为正式验收完成。

## 1. 先按这个顺序做

| 顺序 | 测什么 | 人员/资源 | 记录位置 |
| --- | --- | --- | --- |
| 1 | 启动、三个诊断模型、真实动漫模型、左右方向 | 你自己、摄像头、模型 | 结果总表 A、B |
| 2 | 摄像头错误、校准、保存、清除、回放 | 你自己 | 结果总表 C、D |
| 3 | 三人的动作成功率和中性误触发 | P01/P02/P03、一个观察者 | actions.csv、人员汇总 E |
| 4 | 实时性能、抖动和遮挡恢复 | 你自己、参数导出 | performance.csv、分析 JSON/CSV、总表 F、G |
| 5 | 连续30分钟及各10次模型/摄像头切换 | 你自己；两台摄像头便于验证真实切换 | stability.csv、性能轨迹、总表 H |
| 6 | Chrome复核、整理问题并交回结果 | 你自己 | 结果总表 I 及问题清单 |

建议分两次完成：第一次检查功能与三人动作，第二次测性能和30分钟稳定性。完整执行通常需要约1.5～2小时，问题排查另算。今天只有你一人也能先完成顺序1、2、4、5，三人项目保留“未测”。

结果统一使用：**通过 / 失败 / 未测 / 待复核 / 不适用**。“不适用”只用于模型确实缺少对应能力等合理场景，并写原因；没有人员或设备时填“未测”。

## 2. 准备和启动

### 2.1 准备资源

- 当前电脑接电，使用 Edge，关闭其他占用摄像头的程序。测试时让网页保持前台，不最小化。
- 单人、均匀室内光照、正面，距离先选约50～80cm，之后保持一致；头部动作约±30°。记录眼镜、光照和背景。逆光、大侧脸等放入单独的边界测试。
- 使用三个项目样例：`tests/fixtures/diagnostic-vrm0.vrm`、`diagnostic-vrm1-rich.vrm`、`diagnostic-vrm1-minimal.vrm`。
- 再准备至少一个你有使用权限的完整动漫 `.vrm`，尽量包含左右眨眼、张嘴、微笑和透明头发。记录来源、作者及许可。三个诊断人偶不能代替动漫材质、蒙皮和自然度检查。
- 准备三名测试者，编号 P01/P02/P03；最好由另一人观察角色并记录结果。

### 2.2 建立本次记录文件夹

在项目目录打开 PowerShell，执行：

```powershell
# 在检出的 AniMirror 项目根目录执行以下命令。
New-Item -ItemType Directory -Path '.cache/final-tests/R01' -Force | Out-Null
Copy-Item -Path 'docs/final-test-templates/*' -Destination '.cache/final-tests/R01'
git rev-parse HEAD
```

把最后输出的提交号填入 `RESULTS_TEMPLATE.md`，本轮编号为 R01。后续复测用 R02、R03 等新文件夹，保留原结果。`.cache` 不加入 Git；可把该文件夹路径交给我读取。

已有个人配置时，先在界面点击“导出 JSON”保存备份。不要在三人实验前忘记备份，因为当前界面只有一个默认个人校准，下一人会覆盖它。

### 2.3 启动同一份生产构建

如果 `http://127.0.0.1:4173` 仍能打开，就使用它。在记录里注明地址。否则在项目目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev.ps1 -Preview
```

保持终端开着，打开 `http://127.0.0.1:4173`。结束服务按 Ctrl+C。若提示端口占用，先检查是不是已有一个预览终端；不要同时启动第二个。所有正式测试始终使用相同地址，`localhost`、`127.0.0.1` 和不同端口的浏览器配置存储彼此独立。

若需要重新构建，按根目录 README 的 `pnpm build` 操作。新下载的构建包可解压后执行 `node scripts/serve-build.mjs`。不要双击 `dist/index.html`。

在 Edge 地址栏打开 `edge://version`，记录版本；摄像头型号记录 Windows 设置或设备厂商给出的名称。模型哈希可用：

```powershell
Get-FileHash -LiteralPath 'D:\你的模型路径\角色.vrm' -Algorithm SHA256
```

`RESULTS_TEMPLATE.md` 中的测试日期、浏览器、摄像头、模型哈希与基线配置均要填写实际值。

## 3. A：模型与预览（先不开摄像头）

按下表逐项操作，每完成一项在结果总表填写结论。

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| A01 | 依次导入三个诊断模型，试文件选择和拖入 | 全部可见；报告版本分别为0、1、1；丰富样例有有效表情；minimal明确提示缺失眨眼/张嘴等 |
| A02 | 在“半身”“头部”之间切换，拖动旋转，滚轮缩放，改背景，点“重置视角” | 无黑屏、模型消失或错位；重置后能看到头部与头发；界面正常响应 |
| A03 | 导入真实动漫模型，检查脸、眼球、睫毛、头发、透明部分、衣服；旋转侧面 | 不出现明显材质丢失、黑脸、透明排序错误或蒙皮破损；记录截图和模型哈希 |
| A04 | 保持正常模型，尝试导入损坏文件和超限文件 | 提示原因，原角色保留，可继续旋转及试动 |
| A05 | 在真实模型上逐个试动所有打算使用的目标 | 报告“可驱动”的通道实际能产生预期形变；空绑定/缺失通道不伪装成可驱动 |

为 A04 创建两个仅用于测试的新文件：

```powershell
[System.IO.File]::WriteAllBytes((Join-Path (Get-Location) '.cache/final-tests/R01/broken.vrm'), [byte[]](1,2,3,4))
$oversizePath = Join-Path (Get-Location) '.cache/final-tests/R01/overlimit.vrm'
$oversizeStream = [System.IO.File]::Open($oversizePath, [System.IO.FileMode]::Create)
try { $oversizeStream.SetLength(100 * 1024 * 1024 + 1) } finally { $oversizeStream.Dispose() }
```

超限文件会占用约100MB文件空间；用完可以只删除这两个明确命名的测试文件。不要改坏原模型。外部贴图引用等复杂损坏已经有自动测试，若手上有相关样例可补测并记录来源。

## 4. B：确认映射与真实左右方向

先使用 `diagnostic-vrm1-rich.vrm`，再对 VRM0 和真实动漫模型重复。

1. 切到“映射与调节”。对 `blinkLeft`、`blinkRight`、`aa` 等规则点“试动”；一次约1.5秒。“停止试动”应立即回到正常驱动。
2. 左右按**角色自身**判断：角色面向你时，角色左眼在屏幕右侧。左眼规则应只闭角色左眼；右眼同理。
3. 试动 `happy` 等微笑目标，确认效果后勾选“近似映射 · 已确认”。未确认时应保持不驱动。只有整体 `blink` 的模型无法独立闭左右眼，应明确记录为近似/独立左右不适用。
4. 开启摄像头；完成第5节的校准后，分别向本人左/右转头、点头/抬头、左右歪头，每项做5次。角色应做对应的自身方向动作。
5. 关闭再打开“镜像摄像头预览”，重复左右闭眼和转头。镜像只改变视频，角色动作左右语义应保持一致。
6. 试张嘴、微笑同时眨眼。若模型自带表情覆盖规则导致冲突，记录模型、规则和截图；不得仅凭某个系数升高就判动作正确。
7. 模型有眉毛/视线目标时，测试抬眉和上下左右视线。仅有眼骨、没有视线表情时，当前版本不驱动眼骨，填“不适用”。

通过标准：没有持续左右反转或头部轴向反转；模型具备的目标能正确试动与实时跟随。VRM0与VRM1都要检查。发生反转时先确认观察的是角色自身左右，然后记录为问题，不用镜像开关掩盖它。

## 5. C：摄像头、校准和异常恢复

### 5.1 开启、暂停与关闭

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| C01 | 选择真实设备，点“开启摄像头”，允许权限 | 出现“追踪运行中”；脸进入画面后角色跟随，脸离开后逐渐回正 |
| C02 | 点“暂停追踪”，继续动脸，再点“继续追踪” | 暂停不继续响应新动作，角色短暂保持后回正；摄像头保持连接；继续后恢复 |
| C03 | 点“关闭摄像头” | 状态显示已关闭，视频停止，相机使用指示停止；之后可重新启动。确认没有其他程序正在使用该设备 |
| C04 | 拒绝此站点摄像头权限，再点开启；随后通过地址栏站点权限改为允许 | 拒绝时有明确提示；允许后可重试，不需重装应用 |
| C05 | 让其他应用占用摄像头，再尝试开启 | 若系统拒绝共享，提示占用/无法读取；解除占用后可恢复。若系统支持共享，记录“共享成功，独占错误未触发”，不伪造错误测试通过 |
| C06 | 运行时拔出USB摄像头，再插回并重新选择/启动 | 提示断开/不可用，能重新启动。只有内置摄像头时此项填“未测” |

相机指示灯不是所有设备都一致；可同时查看浏览器相机使用状态。开发者工具的 Sources/源代码线程列表可辅助检查：本应用启动时只有一个 `face.worker`，关闭后不应继续存在该工作线程。普通相机画面能显示而角色不动，仍需要检查追踪器是否真正运行。

### 5.2 正常校准与无效采样

1. 先放松面部、自然睁眼闭嘴，点“采集中性脸”，保持3秒，等“本步已保存”。
2. 选“闭眼”，轻闭双眼，点“采集闭眼”，保持3秒。
3. 选“张嘴”，自然张开，点“采集张嘴”，保持3秒。
4. 选“微笑”，明显但不过分地抬两侧嘴角，点“采集微笑”，保持3秒。
5. 支持眉毛时再做“抬眉（可选）”。完成后导出配置，例如 `P01-config.json`。
6. 故意让脸离开画面后采样，应提示有效样本不足；重做清楚动作应能保存。
7. 重新采集中性脸，旧动作幅度应被重置，随后重新做闭眼/张嘴/微笑；不要把刚刚清除动作范围的配置拿去做正式计数。
8. 启动某步采样后“暂停追踪”，再继续，应能重试。需要测试清除并发时，先备份配置，采样期间点“清除全部本地配置”，等待超过3秒并刷新，旧校准不应恢复。

通过标准：无效采样不假装成功；正常四步可保存；换模型时个人校准可复用；采样中断或清除后旧结果不复活。

## 6. D：保存、重新打开、JSON与参数回放

### 6.1 配置恢复

1. 导入丰富模型，改一条映射权重、一个通道增益、背景色、取景，点“保存配置”，导出 `R01-config.json`。
2. 刷新：模型本身不会自动恢复，这是设计行为。重新选择**同一份文件**，应按文件哈希恢复模型配置、UI和个人校准。
3. 切换另一模型：个人校准保留，模型映射独立。切回原模型后恢复它的已保存值。
4. 当前加载另一个模型时导入 `R01-config.json`，应拒绝哈希不匹配。切回正确模型再导入，应成功。
5. 复制配置为 `invalid-version.json`，用文本编辑器将最外层 `schemaVersion` 改为999，导入应拒绝且界面继续可用。原备份不改动。
6. 备份后点“清除全部本地配置”，刷新并重新选原模型：旧调节和校准不恢复。需要恢复个人环境时再主动导入备份。

清除测试不要与正式三人实验同时进行；它会删除当前浏览器此地址中的全部应用配置。

### 6.2 参数录制与回放

1. 展开“诊断与参数回放”，摄像头运行时点“录制参数 · 最多30秒”。
2. 用约10秒做眨眼、张嘴、转头，然后“停止录制”“导出参数”，保存为 `R01-motion.json`。
3. 点“回放”：摄像头应进入暂停连接状态，预览显示“参数回放”，动作按片段播放。
4. 导入刚导出的参数再回放，顺序和结果应一致；自然结束后退出回放。
5. 回放中改“风格预设”或点击映射“试动”，应退出旧参数回放并使用新的操作。
6. 修改一份参数文件的 `schemaVersion` 为999，导入应拒绝。原片段保留。

参数文件应只有时间、姿态、具名系数和推理耗时等数据，不包含视频。录制最长30秒，60秒测试需要分两段保存。回放期间显示的推理速率不能用于实时摄像头性能验收。

## 7. E：三名测试者的重复动作与中性状态

### 7.1 固定条件和成功规则

使用能力完整的同一模型，确保左右眨眼、张嘴、微笑映射已启用。自然预设、平滑0.50、头部增益1.00作为默认起点；若需调节，先调完、导出配置、记录数值，再开始正式计数。本轮计数期间不改配置。

每人先完成完整个人校准，分别保存 `P01-config.json`、`P02-config.json`、`P03-config.json`。记录从选择规范模型到完成校准并能基本驱动的时间，目标≤3分钟。诊断/非标准模型耗时单列。

沿用验收表预先约定的规则：提示动作后2秒内，对应有效目标驱动值超过0.6、持续至少两个真实渲染帧，同时观察者确认角色可见动作和方向正确。恢复到低于0.2后再做下一次。原始 MediaPipe 输入系数不是目标驱动值；不能直接把诊断面板的输入数值当成成功。

当前应用参数导出保存输入，附带分析工具可以计算固定60Hz回放的目标合成值，但它不能单独证明现场两个真实渲染帧或模型覆盖后的实际形变。因此将“可见结果”和“数值复核”分开填表：能观察动作但数值证据不足时填“待复核”，保留参数片段及时间说明交给我检查；不要把这一限制写成定量已通过。

### 7.2 每人怎么做

1. 按“闭双眼再睁开”做20次；然后“张嘴再闭合”20次；最后“微笑再放松”20次。每次有明确提示，两次之间回到中性状态。
2. 观察者在 `actions.csv` 每次填写可见结果、数值复核结果、最终结果及失败原因。眨眼20次是双眼动作；另外各做5次单侧闭眼检查左右，单侧动作不混入20次双眼成功率。不能自主单侧闭眼时记原因。
3. 为便于数值复核，可每4次动作保存一段约20秒参数：录制起点设为0秒，在0、5、10、15秒给动作提示，2秒内执行，余下时间放松。每个动作5段，共20次。文件名如 `P01-blink-01.json`。观察者记录实际提示偏移，时刻不清楚时保留“待复核”。
4. 导出与该片段匹配的个人/模型配置。选择/调节规则后没有重新导出的旧配置不能用于数值判断。
5. 每种动作合计至少18/20才达到90%；P01/P02/P03分别评判。某人不达标应记录具体失败，不以三人平均值覆盖失败。
6. 每人自然中性脸保持60秒，观察明显误闭眼/张嘴/微笑，目标≤2次；正常自然眨眼不计为错误。可把60秒参数分成两段30秒保存。不要要求人完全不眨眼来制造低误触发。

模型确实缺少对应通道时该动作记“不适用”，换能力完整模型才能完成必测闭环。三位测试者全部完成后，填人员汇总表。

## 8. F：实时性能

1. 选择本轮固定模型、配置、取景和摄像头；请求条件是720p、推理缩至宽640像素。浏览器和摄像头可能实际协商成其他尺寸，要记录实际值。
2. 开启摄像头，预热60秒。保持均匀光照、有效人脸、前台显示，不进行模型切换。
3. 展开诊断。在接下来60秒内每2秒填写 `performance.csv`，共30条：预览右上角的渲染FPS、推理帧/秒、推理耗时、处理P95。
4. 填最小渲染FPS、最小/平均推理吞吐，以及各采样时刻的处理P95最大值；如有明显掉帧，写时间点和原因，不只截最好的一帧。
5. 目标：稳定渲染≥30FPS（60是更高目标）、推理吞吐≥20FPS、处理到渲染提交P95≤100ms。重载/预热/追踪丢失应分开标注，不混作稳定运行达标。

诊断P95取最近最多300个有效、已驱动帧，是滚动窗口；**多个窗口P95不能平均成整场P95**。按本表只能报告窗口检查，整场精确P95仍需开发者复核。推理耗时也不是全部处理延迟；应用指标不包含摄像头传感器到屏幕显示的完整延迟。

如要确认实际摄像头协商值，可按F12打开 Console/控制台，执行以下只读命令，把结果抄进环境表：

```javascript
document.querySelector('video')?.srcObject?.getVideoTracks()[0]?.getSettings()
```

测运行性能时先不录浏览器性能轨迹，避免把采样开销混入基准。之后单独在 Performance/性能工具录30秒代表性运行，停止后通过 Save profile → Save trace 保存；记录这份附加采样是否明显影响帧率。[Edge 官方性能工具说明](https://learn.microsoft.com/en-us/microsoft-edge/devtools/performance/reference)

## 9. G：平滑抖动、快速动作和恢复

### 9.1 录制真正静止的片段

1. 完成校准，固定自然预设、平滑0.50等设置，保存并导出 `P01-config.json`。
2. 预热后保持正面与头部静止，放松面部，录制约20秒，保存 `P01-static.json`。此片段不要刻意做动作；自然眨眼可保留并单独注记。
3. 本轮预先选定**头部三轴合成RMS**为主指标，所有驱动表情RMS也一并报告；表情中的自然眨眼和刻意动作不能直接解释为抖动。不要看完结果再挑降幅最大的通道。
4. 如果有脸丢失、移动、重校准或配置变化，重新采集静止片段，并保留失败原因。

### 9.2 一条命令生成对照报告

分析工具需要源码工作区和已安装依赖；构建zip里不包含它。在项目目录执行，两个输入都来自同一次测试：

```powershell
node scripts/evaluate-final-test.mjs .cache/final-tests/R01/P01-config.json .cache/final-tests/R01/P01-static.json .cache/final-tests/R01/P01-static-analysis
```

如果新开的 PowerShell 提示找不到 `node`，这台电脑可用已配置的运行时执行同一命令：

```powershell
& "$env:USERPROFILE\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe" scripts/evaluate-final-test.mjs .cache/final-tests/R01/P01-config.json .cache/final-tests/R01/P01-static.json .cache/final-tests/R01/P01-static-analysis
```

文件若仍在浏览器“下载”目录，先复制到 R01，并按上述名字重命名。该工具默认排除首1秒，用同一段输入、同一校准、同一映射，比较“平滑0”与配置中的平滑。

输出：

- `P01-static-analysis.json`：时间范围、样本数、丢脸样本数、每轴/每目标RMS与降低百分比。
- `P01-static-analysis.csv`：固定60Hz时钟逐帧的 baseline/selected 头部弧度与目标合成值。

检查 JSON 的 `selectedSmoothing` 是你记录的非零值；`excludedNonLiveSamples` 对本次静止实验应为0。`headCombined.reductionPercent` 目标≥30。RMS围绕各自均值计算，不把固定偏转角误认为抖动。结果为 `null` 表示无平滑基线几乎无可测噪声，此时填“无法衡量/待复核”，不能当作100%改善；负数表示抖动增加。

该工具读取的是录制输入，输出是VRM表情覆盖/二值规则之前的合成值；不检测人有没有真的静止，也不测现场FPS或真实动作延迟。`synthetic-face-sequence.json` 中含刻意运动，适合检查工具能运行，**不适合作为静止抖动验收数据**。

### 9.3 快速动作与遮挡

1. 正常眨眼和快速张嘴各做20次。记录有无漏动作、角色动作明显拖后或眨眼变成缓慢闭眼。不能只凭RMS降低就宣布平滑合格。
2. 不改配置，遮住脸或移出画面2秒，再回到相同正面位置；重复5次。
3. 检查短暂保持、逐渐回正、恢复渐变。目标是恢复脸后1秒内稳定驱动，没有明显姿态跳变。页头状态每秒更新，不适合精确计时；需要时录角色画面，按录像时间复核。
4. 保存一次快速动作片段和一次遮挡恢复片段。需要看某段目标驱动值，可指定分析范围：

```powershell
node scripts/evaluate-final-test.mjs .cache/final-tests/R01/P01-config.json .cache/final-tests/R01/P01-motion.json .cache/final-tests/R01/P01-motion-analysis 0 8
```

这里0和8是秒。动作片段的CSV可辅助查看动作窗口，JSON里的RMS降幅不能再当静止抖动成绩。连续两个CSV采样对应固定回放tick，不代表现场两个真实渲染帧。

## 10. H：连续30分钟和资源释放

先准备保存过配置的VRM0、丰富VRM1、缺失通道VRM1。若有两台摄像头，编号CAM-A/CAM-B，确认都能单独工作；只用同一相机关闭再开启可验证重启，但不能替代“真实设备切换10次”，后一项仍记未测。

| 时间 | 操作 |
| --- | --- |
| 0分 | 开始计时，导入丰富模型并开启CAM-A，记录FPS/推理及初始内存证据 |
| 2、4、6、8、10分 | 每个时间点换一次模型、换一次摄像头并点开启；累计5次各类切换 |
| 12、14、16、18、20分 | 同样每次各换一次，累计10次模型切换与10次真实摄像头切换 |
| 25分 | 保持运行，检查动作/错误/帧率，记录资源证据 |
| 30分 | 回到最初丰富模型和CAM-A，记录相同条件，最后关闭摄像头并检查释放 |

每次模型切换都选择不同文件；相机选择新设备后要点“开启摄像头”。切换耗时与预热单独记录。每5分钟做几次眨眼、张嘴、微笑、三轴；不得挂着空画面运行30分钟就判面捕稳定。

使用 `stability.csv` 记录每次切换；0、10、20、30分钟保存截图，标注当时模型与相机，记录出现的错误与恢复方法。重点比较0分与30分回到相同模型、相机后的资源证据。Performance工具可单独记录初始/末尾各30秒轨迹并勾选Memory，比较JS Heap。必要时用 Memory/内存工具的 Heap snapshot 保存同模型条件下的快照，结合垃圾回收后的趋势检查持续累积。[Edge 官方内存诊断说明](https://learn.microsoft.com/en-us/microsoft-edge/devtools/memory-problems/)

通过标准：不崩溃、不重复推理，切换后旧模型/Worker/媒体轨道不持续累积，最后关闭能释放。不同模型大小不同，比较内存时必须回到同一模型和同一状态。JS Heap没有增长也不能单独证明GPU纹理无泄漏；若证据不足或出现持续增长，把快照/轨迹交给我复核，填“待复核”。不要为了取得好看曲线而在测试途中刷新页面。

## 11. I：本地网络与Chrome复核

### 11.1 运行时无上传

1. 开摄像头前打开F12 → Network/网络，保持记录并打开Preserve log/保留日志。
2. 刷新页面，导入模型、开启摄像头、做动作、录制参数、保存配置、关闭摄像头。
3. 看请求域名和方法：应用资源应来自本次 `127.0.0.1:4173`；不应出现把模型/视频/人脸数据发往外部地址的请求。展开疑似POST/PUT请求看载荷；关闭其他标签和扩展可减少干扰。
4. 保存网络证据；需要时导出HAR，先检查其中是否含你不想分享的信息。Network只记录打开工具之后的活动，所以必须先打开再刷新。[Edge 官方网络工具说明](https://learn.microsoft.com/en-us/microsoft-edge/devtools/network/)
5. 本地服务器继续运行时断开互联网，刷新并重新导入、开启摄像头，仍应工作。断网不关闭本地服务器。

### 11.2 Chrome

计划支持Chrome和Edge。若机器有Chrome，再在相同地址做：三个模型导入、真实摄像头启动/暂停/关闭、四步校准、同模型配置刷新恢复、5次眨眼/张嘴/微笑、5分钟运行，并记录浏览器版本。Chrome配置不从Edge自动共享，可用配置JSON主动导入。

没有Chrome时填“Chrome未测”；本轮Edge通过不能自动写成两个浏览器都通过。若正式发布范围仍包括Chrome，需要补齐它的验证。

## 12. 怎么判断可以正式结束

同时检查：

- 所有P0使用闭环项目均通过，没有阻止导入、关闭摄像头、校准、驱动、恢复配置的问题。
- 三类合规样例按实际能力工作；真实动漫模型材质与动作方向检查有证据。
- 三人每项至少18/20，中性误触发≤2次；缺失能力与未测不混入成功率。
- 性能、静止RMS≥30%改善、快速动作、遮挡恢复和30分钟/10次切换有足够证据；滚动P95和离线输出的限制已经标明，需要的定量复核完成。
- 配置清除后不复活，关闭相机后停止占用，运行时没有图像上传。
- Chrome/Edge支持范围与实际验证一致；失败修复后，原步骤复测并保留旧记录。

完成后把 R01 文件夹路径发给我，并简单说明“哪些通过、哪些失败、哪些待复核”。我可以读取表格、参数、配置和日志继续处理，不必复制整份文档到聊天。真实人物视频不是默认所需材料；必要的角色画面录像可单独说明保存位置。

## 13. 每个问题怎么反馈

在 `RESULTS_TEMPLATE.md` 末尾复制一条问题格式：

```text
问题编号：F-001
测试项目：例如 B-左右眨眼
浏览器版本 / 模型文件哈希 / 配置文件名：
前置条件：导入哪个模型、完成哪几步校准、摄像头是哪台
复现步骤：1... 2... 3...
预期：左眼动作只闭角色左眼
实际：两眼同时闭合 / 无动作 / 反向 / 报错原文
发生次数：例如5次中4次
证据文件：截图、角色录像时间点、参数JSON、配置JSON、性能轨迹
严重程度：阻止使用 / 功能错误 / 质量问题 / 一般观感
```

先保存证据再重试。变更平滑/映射/光照等条件后另记一轮；修复后只重测受影响项目及必要闭环，不需要每次无条件重跑所有项目。
